# HitFeelDemo 打击感优化执行计划

## 目标与范围

以 `HitFeelDemo.unity` 作为可重复的打击反馈实验场，逐项验证命中时序、程序化反馈、屏幕效果及水墨粒子组合。优化始终以真实命中事件为触发条件；未命中不播放任何命中反馈。

本计划限于 HitFeelDemo，不改动 Battle 核心流程、不迁移渲染管线，也不扩展正式攻击系统。当前场景继续使用“测试攻击”按钮和单次目标攻击；新效果应能独立开关，扣血与命中状态不受效果开关影响。

## 视频结论与现状基线

视频把打击效果归纳为四类：程序化效果、屏幕后处理、贴图与粒子、Shader 表现。制作时将数据、触发逻辑和视觉表现分开组合；普通攻击应保持克制，大招或强打击再使用更强的镜头与屏幕效果。

当前 Demo 已有以下效果及独立开关：

| 效果 | 当前默认值 / 资源 |
|---|---|
| 命中顿帧 | `0.06` 秒，命中时将 `Time.timeScale` 暂停，并用非缩放时间恢复 |
| 命中音效 | `Audio_BulletAtk.wav` |
| 命中特效 | 场景当前绑定的 `Assets/Art/Effects/FX/gw/Hit.prefab`，在实际命中表面播放，清理时间 `2` 秒 |
| 敌人闪白 | `0.12` 秒 |
| 敌人击退 | 距离 `0.25`，时长 `0.12` 秒 |
| 镜头震动 | 幅度 `0.08`，时长 `0.12` 秒 |

敌人生命值为 `1000`，每次命中伤害为 `10`，死亡后不销毁。当前 Demo 使用实际命中事件触发反馈；场景已添加拖尾、四项屏幕效果和水墨效果，并为 12 项反馈分别配置开关。下面的基线仍记录优化前数值，新增效果及普通/强打击对照参数见“调参记录”。

## 分阶段执行

### 阶段一：建立基准并确认命中时序

- [ ] 在 Play Mode 录制当前默认表现，记录攻击发射、命中、扣血和反馈开始的时间点。
- [x] 保持现有真实命中事件作为唯一反馈入口；不得以按钮点击或弹体发射代替命中。
- [x] 在 Editor 中分别验证命中与挥空，检查生命值变化、状态文本及命中反馈触发。
- [ ] 后续每轮只调整一个主要变量，并保留前后录屏与参数。

**验收：** 命中时扣血并触发反馈；挥空时不扣血、不触发命中特效、音效、顿帧或受击反馈。

### 阶段二：调准核心反馈与顿帧

- [ ] 以当前 `0.06` 秒顿帧为基准，对比 `0.04`、`0.08`、`0.12` 秒；重击可额外试到 `0.15–0.20` 秒，避免把长顿帧直接用于普通命中。
- [x] 检查顿帧、屏幕反馈与墨迹由实际命中事件触发；挥空未增加命中计数或扣血。
- [x] 验证顿帧结束、控制器禁用及退出 Play Mode 后 `Time.timeScale` 恢复为 `1`。
- [ ] 保留音效、接触点粒子、闪白、击退、镜头震动各自的独立开关，逐一确认关闭某项不会屏蔽其余反馈。

**验收：** 命中瞬间清楚但不妨碍下一次操作；连续命中不会遗留暂停状态或叠加错误位移。

### 阶段三：增加程序化拖影

- [x] 为测试弹体 Prefab 增加可关闭的 `TrailRenderer` 拖尾，普通显示时间 `0.22` 秒、宽度倍率 `0.18`；强打击分别乘以 `1.25` 与 `1.35`。
- [x] 拖尾跟随弹体移动；弹体销毁时停止发射并按拖尾时间清理独立残影对象。
- [ ] 角色肢体拉伸暂不纳入首轮：当前场景为几何占位体，没有角色骨骼动画；待替换为角色模型后再评估网格拉伸与 Shader 拖影。

**验收：** 拖尾只跟随弹体运动；关闭拖尾后攻击、命中和其他反馈保持不变。

### 阶段四：添加独立屏幕效果

- [x] 已确认项目使用 URP `17.0.3`；通过 Demo 专用 Renderer Feature 接入当前 Renderer Data，不迁移管线。
- [x] 提供局部径向模糊、黑白、反色/色彩失真、冲击光圈四个独立开关，均由实际命中事件启动。
- [x] 以命中点屏幕坐标定位效果，使用非缩放时间淡入淡出；效果结束或相机组件禁用后清除状态。
- [x] 普通档使用低强度局部反馈；强档增加持续时间与强度，不扩大为全屏常驻效果。

**验收：** 单独开关每种效果只影响自身；连续命中或组件禁用后画面恢复，不残留 Volume、材质或相机状态。

### 阶段五：组合水墨贴图与粒子

- [x] 保留场景现有 `Hit.prefab` 作为基础命中特效，另设独立“水墨效果”开关。
- [x] 使用 Demo 自有透明墨迹 Sprite 在命中点叠加稳定主体，并按粒子尺寸、速度和生命周期范围生成少量随机细节。
- [x] 首轮只实现贴图与粒子组合，不增加额外高成本溶解/扭曲 Shader。
- [ ] 控制特效尺寸、时长和透明度，确保不遮挡敌人与弹体命中位置。

**验收：** 墨迹位于实际命中点并随受击方向合理展开；开关关闭后黄色基础特效仍正常工作。

### 阶段六：普通命中与强打击分层

| 反馈 | 普通命中 | 重击 / 终结技参考 |
|---|---|---|
| 顿帧与镜头震动 | 短、轻，以当前值为起点调参 | 可适度延长或增强，需避免连续震屏 |
| 音效、闪白、击退 | 清晰但克制 | 加强力度或受击反应，不靠堆叠粒子替代差异 |
| 拖尾与接触点特效 | 保持命中可读 | 可增加拖尾长度、墨迹范围或粒子量 |
| 屏幕后处理 | 默认关闭或低强度局部效果 | 可短暂组合模糊、黑白、反色/失真与冲击光圈 |

- [x] 保留单按钮测试流程，通过 Inspector 的普通/强打击预设配置对照参数，不增加正式战斗招式或输入逻辑。
- [ ] 逐项组合效果，确认强度差异来自反馈层级和参数，而不是无节制叠加所有效果。

## 回归验收清单

- [x] 命中敌人时生命值正确下降、命中状态更新；实际命中会启动配置的反馈。
- [x] 将敌人移出弹道后仍可发射，但不扣血、不增加命中计数。
- [ ] 逐项关闭所有反馈开关，确认每项只影响自身；全部关闭时仍可正常攻击和扣血。
- [x] 连续触发 20 次攻击后敌人未销毁，镜头与敌人位置未累积偏移。
- [x] 命中顿帧结束、禁用控制器及退出 Play Mode 后，`Time.timeScale` 恢复正常。
- [ ] 屏幕效果结束后相机、后处理参数和材质均恢复；没有残留墨迹、粒子或拖尾。
- [ ] 在目标帧率及低性能设备上检查屏幕效果与粒子开销，并记录测试环境和结果。
- [ ] 保存优化前后录屏及最终参数，确保普通命中与强打击能被清楚区分。

## 本轮 Editor 验收记录

- 环境：Unity `6000.5.0f1`，Windows Editor；运行时由 Unity MCP 逐次触发按钮回调，测试后恢复按钮可交互、普通预设和场景初始状态。
- 普通命中：实际命中时扣血、更新状态；观察到屏幕效果进入播放状态、水墨实例生成，顿帧期间 `Time.timeScale = 0`，恢复后为 `1`。
- 挥空：攻击计数增加但命中计数和生命值不变，状态为“已发射”。
- 全部开关关闭：攻击和扣血仍正常；未观察到屏幕效果或水墨实例残留。
- 连续攻击：20 次攻击后累计 23 次命中（含前序测试），生命值为 `770`；敌人位置 `(2.40, 0.85, 0.00)`、相机位置 `(0.00, 3.30, -9.00)`，时间缩放为 `1`，无活动屏幕效果或水墨实例。
- 恢复验证：控制器在顿帧中禁用后，时间缩放由 `0` 恢复至 `1`；强打击预设同一按钮命中后状态正确，顿帧结束后时间缩放为 `1`。
- 拖尾 Prefab 已核实绑定 URP `Particles/Unlit` 材质，宽度倍率 `0.18`、时间 `0.22` 秒、最小顶点间距 `0.035`；水墨粒子亦绑定兼容材质。
- 尚未逐项单独关闭 12 个开关做隔离回归，未录制前后视频，也未在目标设备测帧率；相关验收仍待完成。屏幕/水墨运行状态检查不等同于对视觉观感的逐帧审美验收。
